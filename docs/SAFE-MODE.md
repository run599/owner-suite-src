# 安全模式：可达，但很难进

> 本文件记录对 **OPPO / ColorOS 16（PLE110）** 安全模式入口的实测结论。
> 结论基于系统字节码、资源文件与真机操作，不是网上转述。

---

## 一、结论先说

**安全模式在这台手机上是可用的，但入口被设计得非常难触发。**

- ✅ 可用：实测进入成功，屏幕左下角显示「安全模式」
- ⚠️ 难进：电源菜单没有入口，只能靠**开机瞬间按住音量键**，且窗口极窄
- ✅ 安全模式下占位器**不会失效**（owner 槽位仍被占用）

---

## 二、为什么难进：三层叠加

### 第一层：旧 UI 被废弃，但代码还留着

框架资源里仍有 AOSP 的原始文案：

```
framework-res.apk
  string/reboot_safemode_title    "Reboot to safe mode" / "重新启动并进入安全模式"
  string/reboot_safemode_confirm  "您要重新启动并进入安全模式吗？……"
  string/safeMode                 "安全模式"
```

但 **SystemUI 里搜不到任何 safemode 资源或字符串**（88.5 MB 的 APK，0 命中）。

**也就是说：文案还在框架里，UI 实现被 ColorOS 删掉了。** 这是典型的"功能移除、资源残留"。

### 第二层：电源菜单改成了滑块

ColorOS 16 的电源菜单是**滑块式**（拖动圆圈才能关机/重启），没有可点击、可长按的按钮。

**结果：连"长按关机弹出安全模式"这种旁路也没有了。**

### 第三层：bootloader 抢占了组合键

```
电源 + 音量下  →  Recovery（恢复模式）   ← bootloader 层拦截
```

而 Android 框架的检测是另一套：

```java
// WindowManagerService.detectSafeMode()
if (mWindowManagerServiceExt.disableSafeMode()) return false;   // OPPO 平台开关
if (Settings.Global.getInt(cr, "safe_boot_disallowed", 0) != 0) return false;
waitForInputDevicesReady(1000);                                  // 只等 1 秒
if (getKeyCodeState(..., KEYCODE_VOLUME_DOWN) > 0) → 安全模式
```

**它只在"Android 输入系统刚就绪"的那一瞬间读按键状态。**

按早了 → 被 bootloader 吃掉 → 进 Recovery
按晚了 → 窗口已过 → 正常开机

**两套机制用同一个物理键，bootloader 优先级更高。**

---

## 三、本机核实结果

| 检查项 | 结果 | 含义 |
|---|---|---|
| `oplus.software.disable_safemode` 平台开关 | 未配置 | ROM 没有主动禁用 |
| `safe_boot_disallowed` | `0` | 未被策略禁止 |
| `ro.sys.safemode` | 空 | bootloader 没传"进安全模式"信号 |
| 电源菜单入口 | 无 | SystemUI 无实现 |
| `电源+音量下` | Recovery | bootloader 抢占 |
| **真机操作** | **成功进入** | **能力存在，只是触发窗口窄** |

---

## 四、进入方法（实测可行）

```
① 完全关机
② 按住【音量下键】不放
③ 再按电源键开机（音量下保持按住）
④ 继续按住音量下，直到出现品牌 LOGO 并进入开机
⑤ 成功后左下角显示「安全模式」
```

**要点：**

- 音量下键必须**在按电源之前就开始按**，并**持续按住到开机完成**
- 需要试几次（输入系统就绪窗口只有约 1 秒）
- 如果进了 Recovery（显示恢复菜单），说明按键被 bootloader 拦截，重启重来

---

## 五、安全模式下的状态（实测）

| 项目 | 状态 |
|---|---|
| 第三方应用 | 大部分被停用（92 个中仅 53 个仍启用） |
| **占位器 owner 身份** | **仍然在位**（`dpm list-owners` 显示 ProfileOwner） |
| adb / 无线调试 | **仍然可用**（设置被保留） |
| 桌面 | 只显示系统应用 |

**关键结论：安全模式只停应用，不改系统状态。占位不会被清除。**

---

## 六、为什么 OPPO 要把入口做这么难

两个动机叠加：

1. **防误触**
   普通用户误入安全模式会看到"应用全没了"，以为手机坏了，客服成本极高。

2. **防绕过**
   安全模式能让任何第三方应用失效——如果太好进，**家长管控、企业管控类软件会被轻易绕过**。

**第二条正是关键**：它防的恰恰是"用户用安全模式对抗管控软件"。

这也解释了为什么商业管控软件在拿到 Device Owner 后，第一件事就是设置：

```java
addUserRestriction("no_safe_boot")
```

**它连这道"要靠手速才能过的门"都要焊死。**

---

## 七、对占位器方案的意义

| | 说明 |
|---|---|
| 安全模式仍可作为兜底 | ✅ 但进入成本高（要试几次，且需要物理操作） |
| 更强的兜底 | Recovery → 恢复出厂（代价更大） |
| 占位器的价值 | **正因为兜底很贵，所以"不走到兜底"才更重要** |
| 恶意软件能否阻止用户进入 | ❌ 不能（除非它设了 `no_safe_boot`，而占位器让它拿不到 DO） |

**闭环：占位器 → 恶意软件拿不到 DO → 无法设置 `no_safe_boot` → 安全模式的门永远对用户敞开（虽然难推）。**
